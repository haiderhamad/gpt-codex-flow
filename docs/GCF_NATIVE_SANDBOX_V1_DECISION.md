# GPT Codex Flow — Native Sandbox v1 decision (2026-10-22)

**DECIDED (scope):** The initial cross-platform release uses the Codex CLI's native sandbox for *Codex-launched* work, rather than shipping a signed Owner Broker/XPC execution service. Signed Owner Broker, persistent grant authority, and SQLite replay authorization are **out of v1 scope**. Old research and test fixtures are historical evidence only; they are not installed, enabled or production authorization.

**IMPLEMENTED (existing source):** `scripts/gcf-native-transfer-run.mjs` launches bounded native Codex CLI with `--sandbox workspace-write`, `approval_policy=never`, `sandbox_workspace_write.network_access=false`, `--ignore-user-config`, and `--ephemeral` in ordinary mode. It pins the executable, checks an accepted transfer and clean Git state, and performs postflight review. Owner-started local Auto uses this path and rejects automatic Full Access. `--full-access` is a *separate interactive unsafe bypass*, never a sandbox guarantee. Source MCP editing and Bash tools do **not** inherit Codex's native sandbox.

**v1 restrictions:** Default MCP connection remains approved roots with source write off and Bash off. No remote MCP agent may mint execution grants from files, Task Inbox text or SQLite. No automatic fallback from unsupported/failed sandbox to host execution or `danger-full-access`. Any manual Full Access must remain explicitly labelled high-risk and owner-initiated only; it cannot be described as sandboxed. Do not delete security evidence or previous source work without separately reviewed exact deletion approval.

**Windows CI candidate (2026-10-22):** `.github/workflows/ci.yml` now defines a `windows-latest` build and no-model sandbox-argv contract job. `scripts/gcf-native-sandbox-contract-smoke.mjs` verifies the *actual runner's* default `workspace-write`, network-disabled arguments, rejection of tampered preview commands and explicit distinction from manual `danger-full-access`. The contract test and TypeScript build passed locally on macOS (Exit 0). No Windows workflow has executed yet: the working-tree changes were not committed or pushed. These tests do not exercise Windows OS sandbox containment, MCP tool isolation or a subscribed Codex model.

**NOT VERIFIED / release gates:** An actual Windows Codex CLI sandbox and its network/filesystem boundaries; supported version/CLI flags on both OS families; adversarial probes for outside-root write, sensitive reads, network and symlink escape; confinement of *non-Codex* MCP write/Bash entry points; installed-package/new-machine behavior; and real-user OS-specific execution. A passing Git postflight cannot reverse effects outside the repository, and native sandbox is not equivalent to a signed owner identity broker. Fail closed on unavailable/unsupported sandbox and do not claim Windows production certification without native acceptance.
